这套分数怎么来的

  1. 硬约束过滤：闭馆日、轮椅不可达、低步行人群的陡坡点，直接出局，不参与打分。
  2. 九维加权打分：口碑、兴趣、人群、天气、无障碍、步行、排队、路上、门票，逐项算分后求和。
  3. 时刻卡死：每一站都算「到达 → 排队 → 游览 → 闭馆」四个时刻，任何一步顶到闭馆就整站作废。
  4. 等待折价：开门前干等超过 30 分钟开始扣分，而不是硬性丢弃——硬剪枝会把最优解一起剪掉。
  5. ILS 改顺序：贪心只能单向加，改不了「先去哪」；外层在访问顺序的排列空间做邻域搜索。
  6. 跨天不重复：多日行程把前几天去过的点放进排除集，逐日求解释放耦合。

行程是怎么排出来的

  1. 理解需求：从一句话里取城市、天数、人数、同行人群、兴趣、时段，以及「轮椅 / 腿脚不好 / 怕晒」这类约束。
  2. 过滤：闭馆日、轮椅不可达、步行强度超标的景点直接排除。
  3. 打分：口碑 + 兴趣命中 + 人群适配 + 天气倾向 − 步行强度惩罚 − 排队时间惩罚 − 路上耗时 − 门票。
  4. 排时：按分数贪心插入，每一站都算「移动 + 排队 + 游览」，卡死开放与闭馆时间；11:30–13:30 强制留出午餐。
  5. 改顺序：贪心只能单向加，改不了「先去哪」。外层 ILS 在访问顺序的排列空间做交换 / 移动 / 引入新点，只接受更优解。
  6. 多日：把「N 天」拆成 N 个互相耦合的子问题，逐日求解，前几天去过的点进排除集，住宿固定一家不换店。
  7. 分组：同时有长辈和孩子时拆两组，各排各的，午餐同店汇合；撞点了让亲子组改走别的景点错峰。
